# 🎰 Рулетка с призами

Telegram Mini App — игра «в подарок» одной подруге. **Сервера нет вообще.**

Ссылка на игру: **https://t.me/ruletkaArtema_bot/artemgame**

Отправь её подруге — и всё. Бот запускать не нужно, платить не нужно,
обслуживать нечего. Подруга жмёт ссылку, Телеграм открывает игру во весь экран.

Весь баланс, инвентарь, история и статистика живут в `localStorage` телефона.
Пополняют баланс **промокоды** — вводишь код в разделе «Данные», монеты падают
сразу. Каждый день в 00:00 само начисляется +2000.

Схема максимально простая сознательно: подруга одна и доверенная, играет в
подарок. Статика на GitHub Pages — ноль серверов, ноль расходов, ноль возни.

```
roulette/
├── web/                      ← GitHub Pages (Mini App, статика)
│   ├── index.html
│   ├── style.css
│   ├── app.js                ← вся логика и вся экономика
│   └── codes.js              ← список промокодов (создаётся генератором)
├── .github/workflows/pages.yml   ← автопубликация папки web на Pages
├── bot/                      ← необязателен, см. раздел 2
│   ├── src/index.js
│   ├── tools/gen_codes.js    ← генератор промокодов
│   ├── test/promo_test.js    ← тест промокодов (npm test)
│   ├── Запустить бота.bat    ← запуск двойным щелчком
│   ├── .env.example
│   └── package.json
├── promo-codes.csv           ← таблица кодов для раздачи подруге
└── README.md
```

## 1. Что где лежит и кто что делает

| | Где | Кто меняет |
|---|---|---|
| Баланс, инвентарь, история, статистика | `localStorage` телефона (`roulette.v1`) | приложение |
| Экономика (призы, кейсы, шансы, коэффициенты) | `web/app.js` | ты, вручную |
| Список промокодов | `web/codes.js` | генератор `bot/tools/gen_codes.js` |
| Ссылка на игру | `t.me/ruletkaArtema_bot/artemgame` | задана в BotFather один раз |

Правда о балансе — **в телефоне**. Никакой сверки с сервером, никаких раундов на
проверку. Приложение считает всё само. Это значит:

- офлайн-работа: хоть в авиарежиме, после первой загрузки игра идёт;
- переустановка Telegram или очистка кэша **обнуляют** баланс — это честно
  описано в разделе «Данные», там же экспорт/импорт бэкапа в JSON;
- промокод нельзя «отозвать»: код, введённый один раз, помечается в `usedCodes`
  и повторно не срабатывает, но откатить уже начисленные монеты нельзя.

## 2. Настройка

### Как подруга открывает игру

Один раз в BotFather: `/newapp` → выбрать бота → Title и Short name → указать
адрес приложения. BotFather выдал ссылку:

```
https://t.me/ruletkaArtema_bot/artemgame
```

Эта ссылка и есть вся раздача: подруга её нажимает, Телеграм открывает игру во
весь экран. **Запускать что-либо не нужно.**

Короткое имя `artemgame` хранится в BotFather, а не в коде. Поменять — командой
`/editapp` там же.

### Как приложение попало в интернет

1. Публичный репозиторий на GitHub, имя `skertinsk`.
2. **Settings → Pages → Source: GitHub Actions.** Папку вручную выбирать **не
   нужно**: публикацией занимается `.github/workflows/pages.yml`, он сам берёт
   папку `web` и выкладывает её. Каждый `git push` в `main` пересобирает сайт.
3. Адрес приложения: `https://skertinsky1.github.io/skertinsk/`.

`web/codes.js` и `web/app.js` лежат рядом и тянутся относительно друг друга, так
что отдельно ничего подключать не нужно.

> Публичный репозиторий — обязательное условие: GitHub Pages бесплатен только
> для публичных. Побочный эффект: `promo-codes.csv` со всеми кодами тоже виден
> любому. На баланс подруги это не влияет — он лежит в её телефоне, — но формально
> коды доступны всем. Прятать их есть смысл только вместе с платным GitHub Pro.

### Бот — по желанию

Бот умеет ровно одно: по `/start` прислать кнопку со ссылкой. Он не нужен ни
подруге, ни тебе. Заводить его имеет смысл, только если хочется, чтобы при
`/start` в чате появлялась кнопка.

```bash
cd bot
npm install
npm start
```

Либо двойной щелчок по `bot/Запустить бота.bat` — он сам найдёт Node.

В `bot/.env` (скопируйте `.env.example`) вписывается `BOT_TOKEN` и `WEBAPP_URL`.
Файл в `.gitignore`, поэтому токен в GitHub не попадает.

Бот работает на **long polling** — это исходящие запросы к `api.telegram.org`.
Белый IP, домен, туннель и открытые порты не нужны, но окно должно быть
запущено всё время, пока им пользуются: для подарка это лишний хлопот.

## 3. Промокоды

Баланс пополняют промокоды. В приложении их список — `web/codes.js`, поле ввода —
в разделе **«Данные»**.

| Кодов | Куда падает | Сколько |
|---|---|---|
| 100 | 💰 реальный баланс | 5 000 |
| 200 | 🧪 тестовый баланс | 5 000 |
| **300** | | |

Код одноразовый: введённый код попадает в `state.usedCodes` и второй раз не
работает. Ввод нечувствителен к регистру и дефисам — `ABCD-EFGH-IJKL`,
`abcd-efgh-ijkl` и `ABCDEFGHIJKL` это один и тот же код.

### Как раздать

Файл `promo-codes.csv` — таблица `code,wallet,value`. Это она и есть источник
правды: тебе отдавать подруге коды отсюда, а приложение сверяет ввод с тем же
списком. Пересоздать коды — `node bot/tools/gen_codes.js` (старый список
перезапишется, поэтому запускать один раз).

## 4. Два баланса

| | 💰 Реальный | 🧪 Тестовый |
|---|---|---|
| Откуда | Промокод (100 шт), выигрыш, дневные +2000 | Промокод (200 шт) |
| Рулетка, кости, монетные кейсы | ✅ | ✅ |
| Покупка призов в магазине | ✅ | ❌ |
| Призовой кейс (5 000) | ✅ | ❌ |
| Сгорает в 00:00 | Нет, копятся | Нет |

Активный кошелёк выбирается переключателем под балансами. Ставки, выигрыши и
монетные кейсы идут по нему; призы и призовой кейс — **всегда** по реальному,
поэтому на тестовом их кнопки заблокированы.

Смена суток — по местному времени телефона. В 00:00 статистика дня обнуляется и
реальному балансу **добавляется** 2000 (остаток не сгорает).

## 5. Игры

Кошелёк, призы, история и статистика общие для всех игр.

### 🎰 Рулетка

| Поле | Покрытие | Выплата |
|---|---|---|
| 🔴 Красное | 18 чисел | x2 |
| ⚫ Чёрное | 18 чисел | x2 |
| 🟢 Зеро | 1 число | x36 |

Ставки **копятся** на одном поле (500+500+500 = 1500). Тап — поставить фишку,
удержание (350 мс) — снять. «Повтор» ставит те же суммы, что были на прошлом
спине.

### 🎲 Кости

Ползунок задаёт порог от 2% до 98%, дальше выбираешь сторону:

| Сторона | Выигрывает | Множитель |
|---|---|---|
| ⬇️ Меньше | бросок ниже порога | `0.973 / шанс` |
| ⬆️ Больше | бросок не ниже порога | `0.973 / (1 − шанс)` |

Бросок — целое 0…9999, показывается как `0.0000`…`0.9999`. Стороны с
множителем ≤ 1 автоматически блокируются.

### 🎁 Кейсы

Четыре кейса, у каждого свой барабан. Выбираешь карточкой, потом «Открыть».

| Кейс | Цена | Что выпадает |
|---|---|---|
| 🪙 Монетный | 50 | монеты |
| 💸 Монетный XL | 500 | монеты |
| 💰 Монетный XXL | 2 500 | монеты |
| 🎁 Призовой | 5 000 | предметы из магазина |

#### Монетные кейсы

Редкости и множители общие для всех трёх, выплата = цена × множитель.

| Редкость | Слотов | Шанс | x | 50 | 500 | 2 500 |
|---|---|---|---|---|---|---|
| 🪙 Mil-Spec | 80 | 80% | x0,4 | 20 | 200 | 1 000 |
| 🥈 Restricted | 15 | 15% | x1,5 | 75 | 750 | 3 750 |
| 🥉 Classified | 3 | 3% | x4 | 200 | 2 000 | 10 000 |
| 🔴 Covert | 1 | 1% | x15 | 750 | 7 500 | 37 500 |
| 👑 Special | 1 | 1% | x150 | **7 500** | **75 000** | **375 000** |

Шанс в таблице — ровно то, что на барабане: барабан собран из 100 плиток, один
слот это 1%. Поле `target` в `COIN_CHANCES` — подсказка для настройки (0,26% и
0,64% на 100 слотах недостижимы и становятся 1%). Игроку показывается
`slots / 100`.

Возврат **2,32×** цены, RTP 231,5% — одинаково на всех трёх кейсах. Выплаты заданы
одним множителем на тир, поэтому кейс за 2 500 выдаёт ровно в 50 раз больше
кейса за 50, а шансы у всех трёх одинаковые.

> Это осознанно. Если нужен нейтральный кейс, умножь все множители в
> `COIN_CHANCES` на **0,3718** — получится RTP 97,4%, как в рулетке и костях.

#### 🎁 Призовой кейс — 5 000

Выдаёт **предмет в инвентарь**, монеты не начисляются. Строится из `PRIZES`
автоматически: `price` — цена в магазине (`0` = бесплатный), `weight` — вес в
кейсе (`0` = в кейс не попадает).

Шансы **обратно пропорциональны цене**: при ценах 3000/5000/10000/30000 это
ровно 50/30/15/5, без пустого слота. EV кейса в ценах магазина — 6 000 за 5 000
(RTP 120%), вклад каждого тира одинаков.

| Приз | Цена | Вес | Шанс | Вклад в среднюю |
|---|---|---|---|---|
| 🍦 Мороженка | 3 000 | 50 | 50% | 1 500 |
| 🍫 Шоколадка | 5 000 | 30 | 30% | 1 500 |
| 🍕 Пицца | 10 000 | 15 | 15% | 1 500 |
| 🎁 Желание | 30 000 | 5 | 5% | 1 500 |
| 🤗 Обнимашки | бесплатно | 0 | вне кейса | — |

#### 🎒 Инвентарь

Любой предмет — купленный в магазине и выигранный из призового кейса — падает
сюда (`state.inv[id]`). В 00:00 **не обнуляется** — в этом смысл коллекции.
На баланс не влияет, предмет нельзя продать.

### Общая математика

Коэффициент — полный возврат с фишкой: при выигрыше возвращается `ставка ×
коэффициент` (x36 = 35:1 чистыми).

| Игра | Преимущество казино |
|---|---|
| Рулетка | 2,70% (36/37) |
| Кости | от 2,70% (выплата `floor(ставка × 0.973 / шанс)`) |
| 🪙 Монетный кейс | **в плюс игроку**: 2,32× |
| 🎁 Призовой кейс | **в плюс игроку**: 1,20× |

По костям: монеты целые, выплата округляется **вниз** (`floor`), поэтому на
маленьких фишках край казино растёт. `round` округлял вверх и давал игроку плюс
до +1,75% на пороге 92,5% фишкой 10 — от него отказались.

## 6. Что где менять

| Хочу | Файл и место |
|---|---|
| Цены и веса призов | `PRIZES` в `web/app.js` |
| Цены кейсов и набор | `CASE_ORDER`, `CASES` в `web/app.js` |
| Шансы монетных кейсов | `COIN_CHANCES[].mult` и `target` в `web/app.js` |
| Цена призового кейса | `CASES.items.price` в `web/app.js` |
| Пустой слот в призовом кейсе | `CASE_ITEM_NOTHING` (0 = нет пустого) |
| Край казино в костях | `DICE_RATIO` (0.973) |
| Дневное начисление | `START_BALANCE` (2000) |
| Порог промокодов и их количество | `PLAN` в `bot/tools/gen_codes.js`, затем `node bot/tools/gen_codes.js` |

> Экономика живёт **только** в `web/app.js` — второй копии (как был
> `bot/src/game.js`) больше нет, синхронизировать нечего.

### Про старые типы ставок

В ТЗ было 12 типов ставок (сплит, стрит, угол, линия, дюжина, колонка, чёт/нечёт,
1–18, 19–36) — оставлены только красное / чёрное / зеро. Код остальных удалён,
вернуть можно расширением массива `FIELDS` в начале `web/app.js`.
